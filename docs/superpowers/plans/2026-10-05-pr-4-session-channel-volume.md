# PR 4: Per-Session Channel Volume Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**First execution step:** copy this file to `docs/superpowers/plans/2026-10-05-pr-4-session-channel-volume.md` (repo convention) and include it in Task 1's commit.

**Goal:** Expose pycaw's `IChannelAudioVolume` per session: `getSessionChannelVolumes(target) → number[][]` and `setSessionChannelVolume(target, channel, v) → count`.

**Architecture:** `src/sessions.rs` gains `map_matching(target, f)`: it validates the target, walks `each_session`, and collects `f`'s `Some` results for matching sessions. `apply_to` is rewritten on top of it, so there is still one enumeration and matching path. The getter maps each match to its channel scalars. The setter goes through `apply_to` and leaves out-of-range channels to Windows, which returns `E_INVALIDARG`, so that session isn't counted. `lib.rs` gets two thin wrappers.

**Tech Stack:** Rust 2021, napi-rs 3 (`napi9`), `windows` 0.62.2 (`Win32_Media_Audio` is already enabled and covers `IChannelAudioVolume`), `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-04-pycaw-parity-roadmap-design.md` (PR 4 + "Cross-cutting decisions").

## Context

PRs 1–3 have merged. PR 3 (`4c2f3bd`) added `SessionTarget`, `each_session` and `apply_to` in `src/sessions.rs`. PR 4 depends only on PR 3 and is the smallest PR on the roadmap. Nothing currently reads or writes per-channel session volume.

## Global Constraints

- Flat functions and plain return values. No classes holding COM pointers.
- `SessionTarget = { pid } | { processName } | { instanceId }`, plus an optional `deviceId`. Malformed targets throw `InvalidArg` (reuse `SessionTarget::into_matcher`).
- The getter returns one array per matched session. Unmatched targets, or a missing or unknown device, give `[]`. The setter returns the number of sessions changed, or `0`.
- Invalid arguments always throw, even when nothing matches. That means a volume outside 0..1 or non-finite (`com::validate_volume`), and a `channel` that is not a non-negative integer.
- `channel` is taken as a JS number (`f64`) and validated. napi's `u32` conversion silently turns NaN into 0, which would write channel 0. This uses the same helper as `pid`.
- Pass `std::ptr::null()` as the event-context GUID (PR 9 replaces it).
- Default tests never mutate real sessions. Live checks are gated on `JSCAW_TEST_PROCESS` and restore state in `finally`.
- Ship: a README update, an example (extend `examples/sessions.ts`), a `feat:` commit with no co-author trailers, and green `cargo fmt --check`, `cargo test`, `pnpm build`, `pnpm test` and `bun test`.
- `index.d.ts`/`index.js` are generated by `pnpm build` and untracked. Never hand-edit them.

## Review Focus

1. **`channel: NaN` / `-1` / `1.5`** must throw rather than silently hit channel 0 or `u32::MAX`. → Task 1 JS test plus the Rust unit test on `validate_index`.
2. **`channel` ≥ the session's channel count**: the session is skipped and the setter returns `0`, with no throw. Sessions on one process may differ in channel count. → Task 1 gated live test.
3. **Session whose `IChannelAudioVolume` cast fails**: it is left out of the getter's result rather than failing the call. → Covered by the `filter_map` design. Exercised by the read-only sweep over every listed session, including system sounds.
4. **Malformed or unmatched targets** on both new functions. → Task 1 reuses `BAD_TARGETS`/`UNMATCHED_TARGETS`.
5. **Restoring state**: the live test restores every channel from the pre-test snapshot. → Task 1 `finally`.

```rust
/// JS numbers arrive as `f64`: napi's `u32` conversion silently turns NaN into 0 and -1 into
/// `u32::MAX`, so integer arguments are checked here.
fn validate_index(name: &str, value: f64) -> Result<u32> {
    if value.fract() != 0.0 || !(0.0..=u32::MAX as f64).contains(&value) {
        return Err(Error::new(
            Status::InvalidArg,
            format!("{name} must be a non-negative integer, got {value}"),
        ));
    }
    Ok(value as u32)
}
```

```rust
/// Calls `f` on every session matching `target`, collecting its `Some` results.
fn map_matching<T>(
    target: SessionTarget,
    mut f: impl FnMut(&IAudioSessionControl2) -> Option<T>,
) -> Result<Vec<T>> {
    let (matcher, device_id) = target.into_matcher()?;
    each_session(device_id.as_deref(), |control, pid| {
        if matcher.matches(control, pid) {
            f(control)
        } else {
            None
        }
    })
}

/// Calls `apply` on every session matching `target`; returns how many accepted it.
fn apply_to(
    target: SessionTarget,
    mut apply: impl FnMut(&IAudioSessionControl2) -> windows::core::Result<()>,
) -> Result<u32> {
    Ok(map_matching(target, |control| apply(control).ok())?.len() as u32)
}
```

- [ ] **Step 5: Add the channel functions** after `set_mute`. Add `IChannelAudioVolume` to the `windows::Win32::Media::Audio` import.

```rust
/// One array of 0..1 channel volumes per matching session; sessions that can't be read are skipped.
pub fn get_channel_volumes(target: SessionTarget) -> Result<Vec<Vec<f64>>> {
    map_matching(target, |control| unsafe {
        let channels = control.cast::<IChannelAudioVolume>().ok()?;
        (0..channels.GetChannelCount().ok()?)
            .map(|i| channels.GetChannelVolume(i).ok().map(f64::from))
            .collect()
    })
}

/// A session without `channel` rejects it (`E_INVALIDARG`) and isn't counted.
pub fn set_channel_volume(target: SessionTarget, channel: f64, volume: f64) -> Result<u32> {
    let channel = validate_index("channel", channel)?;
    validate_volume(volume)?;
    apply_to(target, |control| unsafe {
        control
            .cast::<IChannelAudioVolume>()?
            .SetChannelVolume(channel, volume as f32, null())
    })
}
```

# PR 11: `jscaw/magic` high-level layer (pycaw `magic.py`)

## Context

Next PR on `docs/superpowers/specs/2026-10-04-pycaw-parity-roadmap-design.md`. Its prerequisites (PR 3 rich sessions and PR 10 session notifications) have both merged (#42, #56). PR 11 adds pycaw's `magic.py` equivalent: you watch an app by exe name and get one aggregated volume/mute handle that follows its sessions as they appear and expire. It is pure hand-written JS + types with **no native code**. PR 12 (demo) depends on it.

First implementation step: copy this plan to `docs/superpowers/plans/2026-10-06-pr-11-magic.md` (the roadmap's convention), then build it with TDD.

## API (`magic.mjs` + `magic.d.mts`)

```ts
watchApp(exeNames: string | string[], options?: {
  onVolume?(volume: number): void;          // aggregate changed
  onMute?(muted: boolean): void;            // aggregate changed
  onState?(state: 'active' | 'inactive'): void; // aggregate changed (no selfInitiated, always fires)
  onSessionsChanged?(sessions: AudioSession[]): void; // tracked set gained/lost one
  includeSelf?: boolean;                    // default false: skip selfInitiated volume events
}): MagicApp

interface MagicApp {
  readonly sessions: AudioSession[];   // tracked, cached snapshot
  volume: number | null;               // get: max over sessions; null when none. set: fan out
  mute: boolean | null;                // get: any muted wins; null when none. set: fan out
  readonly state: 'active' | 'inactive';
  toggleMute(): void;
  stepVolume(step = 0.1): void;        // clamps to 0..1
  dispose(): void;                     // idempotent
}
```

Notes:
- The roadmap scopes this to the default render device only, like pycaw magic. A `deviceId` option can come later if someone needs it.
- Exe names match case-insensitively, the same way `processName` targets do natively.

## Implementation (`magic.mjs`, ~100 lines)

Reuse the existing native API from `./index.js`: `listSessions`, `onSessionCreated`, `onSessionEvent`, `setSessionVolume` and `setSessionMute`.

1. **Startup.** Subscribe `onSessionCreated` **first**, then seed from `listSessions()`, deduping by `instanceId`. Doing it in this order closes the race between listing and registering. If `onSessionCreated` returns `null` (no default device, as on CI), the app stays inert with zero sessions.
2. **Tracking.** Keep `Map<instanceId, { session, unsubscribe }>`. `track(session)` calls `onSessionEvent({ instanceId }, handler)`, caches the session and fires `onSessionsChanged`.
3. **Handler.**
   - `volumeChanged` updates the cached volume and mute. If the event is external, or `includeSelf` is set, fire `onVolume`/`onMute` only when the aggregate actually changed.
   - `stateChanged` with `expired`, or any `disconnected`, untracks the session (unsubscribe, delete, `onSessionsChanged`). Any other state just updates the cache.
   - Either way, fire `onState` when the aggregate state flips.
4. **Setters.** Call `setSessionVolume`/`setSessionMute({ instanceId }, v)` for each tracked session and update the cache right away, so getters are consistent synchronously. Validation of 0..1 comes for free from the native `validate_volume` throw.
5. **Getters.** Read from the cache, with no native calls.
6. **`dispose`.** Unsubscribe the created-subscription and every session subscription, then clear the map. The process can then exit on its own.

## Tests: `__test__/magic.test.mjs` (TDD, written first)

- The tests import via the **package self-reference** `from 'jscaw/magic'`, so they exercise the `exports` map in-repo. The file can also be copied unchanged into the smoke-test consumer.
- Default tests (no mutation, safe with no audio device):
  - `watchApp('jscaw-no-such-app.exe')` gives `sessions: []`, `volume === null`, `mute === null` and `state === 'inactive'`.
  - Setters, `toggleMute` and `stepVolume` are no-ops.
  - `dispose()` is idempotent, and the test process exits (a leaked subscription would hang `node --test`).
  - Array and single-string `exeNames` are both accepted.
- Gated live test (`JSCAW_TEST_PROCESS`): sessions is non-empty, `volume` and `mute` round-trip, and `stepVolume`/`toggleMute` change the aggregate. A `selfInitiated` change does not fire `onVolume` by default. State is restored and `dispose()` is called in `finally`.
